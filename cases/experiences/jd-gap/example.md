# 同一个 JD，五种不同处理

本轮宿主依据 [合成请求](request.md) 编写并普通自查的示意，不是独立试用、
真实岗位匹配或招聘效果评估。

**当前建议：先确认深圳现场办公，再决定是否做一次有边界的申请。**
已有评测相关经历，但集成部署是确认缺口；现有材料不支持“准确率提升 20%”。
这不等于整个人不适合 AI 产品，也不意味着 SQL 缺失就不能投。

| J1 要求 | 候选人材料与边界 | 当前状态 | 下一步 |
| --- | --- | --- | --- |
| 整理问题类型与评测记录 | U1 自述做过团队原型分类与记录；检查项为团队约定，未看原始表 | 已有支持，仅自述 | 保留具体评测贡献，不写成独立制定标准 |
| 接口异常与人工兜底流程 | U1 自述做过超时转人工流程，R1 未写 | 表达缺口 | 如果之后要求改简历，再加入有自述边界的流程工作 |
| 对照验证效果改善 | R1 的 20% 来自队友口述，无基线、题量或对照 | 证据不足 | 不使用该提升幅度；不能只换个强动词解决 |
| 服务 API 集成与部署 | U1 明确没有做过，队友完成 | 真实缺口 | 申请时如实说明；今晚不临时造部署经历 |
| 深圳现场办公 | U1 尚未决定 | 待确认，硬约束 | 先核实自己的可行性，再决定是否继续投入 |
| SQL 优先 | U1 无 SQL 项目，未说明其他 SQL 使用经验 | 待确认，且属加分项 | 不从缺少项目推断完全不会 SQL，不升成必备条件或据此否定投递 |

材料相关性不提升 confidence：个人活动仍为 SELF_REPORTED，未认证作者或效果。
J1 是合成 JD，仅能说明该文本要求，不能说明真实岗位仍在招。

**今晚最多做三步：**

1. 用约 5 分钟确定现场办公是否可接受；不接受就停止这一机会的准备。
2. 若可接受，用约 10 分钟确认该岗位是否接收尚无个人集成部署实践的候选人；
   先准备给招聘方的问题，由本人决定是否发送，不声称已联系。
3. 剩余约 15 分钟整理已有评测工作与超时转人工流程的事实要点，作为是否投入
   一次申请的依据；不新增学习大计划、不改用户尚未授权修改的简历文件。

没有替用户投递、改写原简历或把计划记成完成。下一次带回现场办公决定与招聘方
对集成实践要求的回复；它们可能改变此机会的投入选择，不直接改变历史经历。
