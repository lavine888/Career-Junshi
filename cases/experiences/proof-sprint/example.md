# 合成示例：先交付补证计划，再检查回传材料

这是手写的示意对话，不是实际工具运行、独立宿主试用或真实求职成效。
示例中的回传日志也是合成材料。报告在聊天交付，未创建文件或启用记忆。

军师：

这三小时只整理已有评测工作的可复现证据，不追补 production 或 30%。
下面是 `evidence-sprint.md` 的内容；全部工作当前都处于待做状态。

## evidence-sprint.md

- **目标**：P-EVAL / C-EVAL，来源 `synthetic:user-request`。团队项目处于 demo；
  个人负责评测与失败分类目前是自述，不能升级成独立工程作者。
- **当前安全表述**：据本人描述，参与团队 Agent 原型，负责评测脚本与失败分类；
  已有工作范围、测量方法和结果待产物核对。撤下 production 与 30%。
- **只补一处缺口**：把已有八条合成样例、运行步骤与失败分类对应起来。
  完成后最多支持一个有边界的本地评测演示，不支持真实用户效果或生产稳定性。
- **产物**：`eval-notes.md`，写清现有脚本入口、环境、样例 ID、预期判定、
  实际结果和失败分析；附所需脚本片段或可授权查看的文件，以及本人改动范围。
- **验收**：按笔记中的实际命令重跑八条现有样例，输出可逐项对应；至少检查
  一条预期失败如何呈现，不能为凑全绿改预期。区分测试通过与 Agent 任务成功。
  若无法重跑，明确记录失败步骤和尚缺条件，不写成复现成功。
- **预算**：周二 60 分钟整理八条样例及预期；周四 60 分钟补运行笔记并重跑；
  周日 60 分钟检查失败、个人改动边界与可用措辞。总计 180 分钟，不额外加时。
- **停止线**：环境恢复超过 30 分钟就改为整理已有日志与缺失条件，减少重跑范围；
  三小时到即停。没有基线与比较就不计算提升，演示未完成就保持待核对措辞。
- **回流**：把笔记、输出、失败样例和个人改动范围回传到本聊天。届时区分
  你报告完成的内容、我实际检查的内容和仍未验证的内容，再决定是否改 C-EVAL。

用户回传：

也没有提高成功率的对照。先保留当前措辞。请贴出笔记里的运行命令与一条完整结果，
尤其是预期失败样例如何判定；不需要上传整份项目。

军师：

根据你贴出的这段日志，可记录一次用户报告的本地合成评测：八条断言通过，
其中两条任务失败被预期识别；这里没有重新运行命令，不能称为独立复现。
你的本周新增产物是运行笔记，也不能把团队共同维护的脚本写成个人独立实现。

当前 C-EVAL 可暂写：“据本人描述，参与团队 Agent 原型的评测与失败分类，本次整理了
八条合成样例的运行笔记；所贴日志报告六条任务成功、两条预期失败。”
保留 P-EVAL、demo 与上述日志来源，不添加“体系”“显著提高”或 production。
