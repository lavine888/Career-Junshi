## decision-review.md

### 原判断与来源

来源 `synthetic:prior-message`，由用户在本聊天贴出，日期未提供；
不是从长期记忆取回。它建议先核对个人贡献并练追问，没有预测通过概率，
也没有断言只会问 ownership。早先仅有用户回忆时，原文与反转条件均为未知；
现在依据新增片段进行对照，保留这两个阶段的来源边界。

原反转条件是“真实追问显示架构取舍是重点时，提高准备优先级”，
停止线是“不补新项目，无法补证就撤下强表述”。

### 实际观察、感觉与未知

| 内容 | 来源与当前边界 |
| --- | --- |
| 用户报告本轮通过，HR 说下一轮另约 | `synthetic:user-recap`；HR 内容是用户转述，非独立核查 |
| 个人贡献被问，架构方案被问约七分钟 | 同一场面试的一次用户复盘，不算多个独立事件 |
| 成功率指标没有被问 | 本次未观察到相关考察，不说明指标风险不存在 |
| 用户感觉架构答得差 | 感觉；不能改写成面试官明确差评 |
| 通过原因、面试官评分与下轮重点 | 未知；目前无因果判断依据 |

### 对照与修正

- 个人贡献确实被问，支持该项准备与本次话题相关；不证明准备有效导致通过。
- 原文没有给架构关注度的定量预测，不能回填成“预测命中”或“预测失败”。
- 原文的架构重评条件得到这次自述问题的支持，可提高下一轮该项准备优先级；
  具体会考多久仍未知。若 HR 或新 JD 后续给出不同重点，再调整。
- 未问指标属于未观察，而非风险被反证。通过结果也不支持把 demo 改成 production。
- 继续同一方向，微调准备；单次结果不足以宣布方向正确、能力不足或需要转行。

### 下一步与停止线

今天四十分钟：前十分钟写出被问的架构问题原话或尽可能准确的回忆并标明不确定处；
二十分钟用已有方案解释一个真实取舍、个人动作和团队边界；最后十分钟检查
回答是否有原始产物支持。没有做过的决策明确说明，不临时造一套架构或开新项目。

观察窗口到下一轮安排或新 JD 到来，再核对考察重点；四十分钟到即停。
P-EVAL 保持团队 demo，评测与失败分类保留自述来源。通过不升级工程作者、
production 或提升 30% 的 Claim；产物来源和测量证据要另行核对。

下次只需在本聊天带回新安排、实际问题或一项原始反馈；这份复盘不覆盖旧判断，
也不自动保存到长期记忆。没有找到旧消息的情况下，保留“原判断未知”，
同样可以完成“新观察 → 当前准备动作”的复盘，但不评价旧预测。
