# 当前构建会话的 Skill 示范 — 合成案例 A

这是构建 Agent 按 SKILL 与三个相关参考完成的示范，不是独立模型评测或真实面试结果。

**今晚先改掉缺证的 production 和“提升 30%”，守住你真实做过的评测与失败分类。**
第二优先级是架构取舍的五层追问；今晚不要再开一个项目。

已知材料：邀请写明明天下午一面；JD 要求评测和架构取舍；据你描述，这是团队原型，
你负责评测，服务与 UI 由队友做。原型说明能支持项目存在，不能证明生产使用或指标。
我推测这些强表述是被问穿的主要风险；不知道面试官实际题目和最终评价。

现在做三件事：

1. 先用保守措辞：“参与团队 Agent 原型，负责评测脚本与失败分类。”这是按你的陈述整理，
   尚未独立核查贡献。没有基线、样本和运维记录，暂时删除 production 与 30%。
2. 用 60–90 分钟练五层：具体做了什么、为什么这样设计、替代方案、怎么测量、什么失败了。
   架构只讲你真正理解与参与的部分，不替队友领功。已生成 [风险图](artifacts/claim-risk-map.md)
   与 [防守提纲](artifacts/project-defense.md)；材料不足，不能填入虚构的技术答案。
3. 你再练一次 90 秒故事：问题 → 个人动作 → 原型结果 → 未验证范围。到时间停止准备并休息，
   面试由你参加。

面试后记录被追问最深的三个问题、自己的回答和明确反馈，再决定下一轮补什么。
强表述无法补证就降低措辞；若一轮通过，也只说明这次通过，不能证明准备造成成功。
