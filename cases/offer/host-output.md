# 当前构建会话的 Skill 示范 — 合成案例 C

这是构建 Agent 按 SKILL 与职业决策 / Offer 参考完成的示范，不是公司排名或真实职业验证。

**按你现在的目标，首选 A；接受前再确认实际 ownership 的兑现条件。**
你已明确未来两年更重视产品 ownership 与技术判断，两份都满足地点和最低薪酬约束。
据你提供的团队交流和主观评分，A 的完整产品责任与学习更强；B 的品牌与薪酬更好。
这些评分表达你的偏好，不是公司质量的客观事实；未来组织变化仍未知。

我已生成 [比较表](artifacts/offer-comparison.md)。下一步只有三件事：

1. Codex 把书面已知条件、用户偏好和未确认信息拆开；评分只能辅助权衡。
2. 你在最早截止时间前确认：A 是否真的能负责需求到评测、谁有最终决策权、经理如何评价成果。
   薪酬、地点与期限以真实书面条款为准。
3. 硬约束仍满足、关键信息确认后，由你接受或拒绝。若目标变成优先薪酬，示例会改选 B。

经理与团队的描述能否兑现无法保证。新信息逆转 ownership 或触犯硬约束时重评；
不为公司名牺牲你已明确的约束。目标和约束没有给齐时，应先问这些信息，而不是先排名。
