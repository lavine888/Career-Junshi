### 当前岗位组合

- **主投：风险产品 / 数据产品经理**——优先选择需要风险场景理解、规则与数据定义、指标设计和跨团队协作的岗位。
- **副投：风控平台产品经理**——只投产品职责清楚、没有要求独立承担底层架构设计的岗位；用下一场面试验证技术沟通能否补齐。
- **探索：纯运营**——可以少量了解职责、收入和成长路径，但现在不作为逃避拒绝的默认转向。
- **降低投入：要求产品经理亲自拥有分布式基础设施架构的岗位**——这与现有经历边界不匹配。

### 可直接使用的定位表述

> 我有五年消费金融产品经验，优势是把风险场景转成需求、数据定义和可衡量指标，并与数据和工程团队推进落地。我没有独立开发分布式存储，系统实现由工程同事负责；我需要负责讲清业务允许怎样的一致性、重复请求如何影响结果、失败后怎样重试或回放，以及用什么指标验收。具体项目中，我会明确说明哪些决定由我参与、哪些由工程团队负责。

这段话只有在后半部分能够用两个真实项目举例时使用；否则删去不能证明的部分。

### 项目防守卡

对每个项目各准备以下答案：

1. **一致性**：哪些状态不能不一致？短暂不一致会给客户、额度、账务或风控决策造成什么后果？
2. **幂等**：同一请求重复发生时，业务上允许生成几个结果？用什么业务键识别重复？技术实现不知道就明确说由工程负责。
3. **重试**：什么失败可以自动重试，什么必须停止或人工介入？如何避免重复执行扩大损失？
4. **回放**：为什么需要回放，回放哪些数据、按哪个规则版本处理，如何审计结果？
5. **贡献边界**：我定义了什么规则或验收指标，参与了什么取舍；工程同事设计和实现了什么？

### 面试中反问

- 入职前三个月最重要的交付物是什么，通常由产品、数据和工程分别承担哪些决定？
