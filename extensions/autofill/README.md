# 军师投递助手

默认无需模型 API 密钥：本地读取简历、OCR 和规则填表；也可选接 DeepSeek、智谱 GLM
或其他 OpenAI 兼容接口，匹配剩余字段、提取复杂事实与起草开放题。
所有模型结果先预览，填写后由本人检查、手动提交，再确认记录实际投递。

侧栏分为三个页签：**填表**用于本次简历、当前页填写和方案核对；**记录**用于收藏、
本人提交确认、进展与备份；**设置**用于国内模型连接和数据管理。首用不必先配置模型。

## 安装

**直接使用发行包，不需要先配置 Python 或模型 API。**

1. [下载 v0.3.2 插件包](https://github.com/lavine888/Career-Junshi/releases/download/autofill-v0.3.2/junshi-autofill-0.3.2.zip)，解压并保留 `junshi-autofill` 文件夹。
2. 打开 `edge://extensions`（Chrome 为 `chrome://extensions`），开启开发人员模式。
3. 点击“加载解压缩的扩展”，选择包含 `manifest.json` 的 `junshi-autofill` 文件夹，再固定扩展图标。

插件和军师 Skill 分别安装，可以单独使用；Skill 安装器不会顺带安装浏览器扩展。
安装后直接看[完成第一次填写](#完成第一次填写)；已有旧版请先看[升级说明](#从旧版升级)。

<details>
<summary>开发者：从源码准备依赖或打包</summary>

如果从源码开始，先准备 Python 3.10+，在仓库根目录运行：

```sh
python extensions/autofill/tools/prepare_vendor.py
```

此步骤下载固定版本的公开 OCR/PDF 组件和中英文识别数据，约几十 MB，
不读取个人材料。依赖与许可证随打包目录分发，使用时不从 CDN 加载代码。

需要打包给自己或试用者时，在准备好依赖后运行（输出路径必须尚不存在）：

```sh
python extensions/autofill/tools/package_extension.py --output /private/junshi-autofill.zip
```

发行包包含本地组件和许可证，不包含个人简历、投递记录或浏览器资料。

## 从旧版升级

先备份记录，把新版本文件更新到原先加载的文件夹，再到浏览器扩展页
对现有扩展点击“重新加载”。若换加载目录，可能成为独立扩展，需恢复备份并重新导入简历。
不要先卸载，以免丢失记录；重新加载后会话密钥需要重填。
解析规则已更新的旧缓存会显示“需重新导入”：旧文字仍可查看，但不能直接确认、更新文字
或发送给模型来绕过检查。重新选择原简历附件并核对即可恢复；历史投递及原投附件指纹不变。

## 完成第一次填写

**导入 → 核对 → 填入 → 检查网页 → 本人提交 → 确认记录**

1. 在招聘网页点击军师图标。在“填表”选择**本次准备投递的简历**，检查识别字段；
   需要时展开“查看或修正识别原文”，再
   点击“确认这份简历，保存在本机”。优先使用军师导出的 `resume-data.json`，
   能保留多段教育和项目结构；也支持 PDF、UTF-8 文字和图片。
2. 图片或无文字层的扫描 PDF，勾选本地中英文 OCR。OCR 只识字，可能认错，
   修改识别文字后要重新确认。普通 PDF 优先提取文字，不必 OCR。
3. 点击“识别并填入确定项”。插件使用 label、placeholder、name、ARIA、
   autocomplete 与中英文字段别名匹配。已有内容保留，未匹配或自定义控件留待处理。
4. 检查实际网页。多页表单每到一页重新点击识别；插件不点击下一步、协议或提交。
   “撤销本轮填写”只撤销仍等于插件填入值的字段，保留本人随后改过的内容。
5. 本人实际提交后，进入“记录”，点击“我已实际提交”。只填表或打开成功页面不会自动算投递。
   招聘进展可在记录卡片的“更新进展”内填写；备份与恢复位于记录页底部。

填写失败时会自动展开明细，区分已填与未完成，不把零成功显示成完成。
多所学校但网页缺少明确分组时，不默认取第一所；缺少某段专业不会让后一段前移。
提供完整日期就保留已有精度，只有年月时不会补造日。

“记录”会显示这条记录属于哪个网页。换了页面后，保存前必须选择“仍记原岗位”或
“改用当前网页”：提交跳到通用成功页可以保留原岗位；换了岗位则选当前网页，旧公司、
岗位、备注、JD 和简历使用确认会清空。切换活动网页或 URL 后，旧方案不能继续填入。
导入或修改简历、重新识别表单都会取消“实际提交的就是这份简历”，需要本人重新核对。

## 可选：接入国内模型 API

1. 进入“设置 → 模型连接”，选择服务商，在插件内填写自己的 API Key。
   不要把密钥发到聊天、反馈或 GitHub。预设基于以下官方文档核对，模型名称可以编辑：

   | 服务商 | API 地址 | 默认模型 |
   |---|---|---|
   | [DeepSeek](https://api-docs.deepseek.com/) | `https://api.deepseek.com` | `deepseek-flash` |
   | [智谱 GLM](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.7-flash) | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.7-flash` |
   | 自定义兼容接口 | 填 Base URL 或完整 `/chat/completions` 地址 | 填服务商提供的模型 ID |

   默认地址和模型无需重复填写，要修改时展开“接口地址与高级选项”。选择自定义接口会自动展开。
   远程地址要求 HTTPS；本机 `localhost` / `127.0.0.1` 可用 HTTP。不同平台的密钥不通用。
   本版本使用通用 Chat Completions，不支持 Anthropic 原生协议或只支持 Responses 的接口。
2. 点击“保存配置并授权 API 地址”，仅申请所填 API 域名的访问权限，尚不发送简历。
   密钥默认只放浏览器会话内存；重启、重载或更新扩展后需重填。
   主动勾选“记住密钥”才以本地明文保存，不使用云同步，不进入投递备份。
3. 可点击“测试连接（仅合成内容）”：发送一次真实请求，只含合成 JSON 任务，不含简历。
   可能产生少量服务商调用费用；失败显示原因，不自动重试或更换服务商。
4. 回到“填表”完成本地识别，展开“补全剩余字段与开放题”，再点击“预览本次 API 请求”。默认只发送剩余事实字段的标签、选项、
   分组与已有资料的类型、ID；模型返回匹配 ID，真实简历值在本机取出。
   不发送简历正文、已填写值、岗位 URL 或 JD；页面标签本身仍可能夹带个人内容，发送前检查。
5. 若需从简历原文提取复杂事实或起草开放题，主动勾选“本次允许发送已确认简历内容和下方 JD”，
   再预览。此时服务商会收到简历来源文字，可能含姓名、联系方式等，适用其数据政策。
   这一选择不自动保存到下一次打开的侧栏。
6. 点击“生成待核对方案”。结果自动展开供检查，不会直接落表；核对后点击“填入已确认的方案”。
   开放题默认未勾选，必须逐项确认后才能填入。事实答案只取已有值或原文片段，缺项不补造。
   已填入的草稿会显示完成状态，后续修改请直接在官网进行，避免覆盖本人后续编辑。

默认给 DeepSeek / GLM 关闭思考模式，使用 JSON 输出；单次请求最多等待25秒，不自动重试。
自定义接口若不支持 JSON 模式可取消对应选项，返回仍须是有效 JSON。
HTTP 401 检查 Key，403 检查模型权限，404 检查地址／模型 ID，429 检查额度／限流。
“移除 API 配置”清理两种密钥存储并尝试撤回对应授权；卸载或“清除本地简历、记录与 API 配置”也会清理密钥。
不把配置已保存、合成服务响应或模型摘录校验等同于事实真实、真实网站接收或真实服务调用通过。

## 复杂字段和开放题也可以不接密钥

在“填表 → 补全剩余字段与开放题”展开“交给现有军师”，导出 `junshi-form-context.json`，把它交给你正在使用的
助手，附上：

> 请用 career-junshi 的投递助手参考，按这个文件生成 junshi-fill-plan JSON。
> 事实值只摘录来源，不猜缺项；开放题写为待本人确认的草稿。

将助手实际生成的 JSON 导入或粘贴回侧栏。插件核对本次表单、简历指纹和来源，
开放题默认未确认，勾选确认后才填入。这条路径多一次文件交接，不能称为
“不依赖模型也能自动生成个性化开放题”。OCR 和字段别名不提供生成能力。

## 接回求职军师

最近投递中的“交给军师继续”只导出选中的一条记录，兼容已有
`junshi.py import-context`，不要求先补齐 Claim 或绑定不存在的简历版本。
原投附件名与 SHA-256 随首次本人提交确认保留；新的简历或反馈不覆盖它。
实际提交时间未提供时写未知，记录时间不伪装成提交时间。
同一规范化链接的重复保存更新同一记录；不同平台的同一招聘流程仍需本人合并判断。

```sh
python scripts/junshi.py import-context --input /private/junshi-career-context.json --mode recruiting --output /private/session-packet.json
```

“导出全部本地记录备份”导出投递记录，不包含整份简历；浏览器卸载扩展会清除
本地存储，卸载前自行备份。本版本不做云同步、个人记忆或 LavineOS 双向写入。

## 边界与验证

这是可试用首版，不承诺任意官网兼容。支持原生输入、文本域、唯一精确匹配的
原生下拉和开放 Shadow DOM。自定义组合框、跨域 iframe、封闭 Shadow DOM、
多段区块缺少可识别分组、动态组件拒绝事件、附件上传等需要人工处理。
不会补造日期中的日，不会截断长答案，也不会把硕士在读推断成已毕业。
证件、密码、验证码、工作资格、薪资、人口统计及协议等留给本人填写。

本地模式不发送网络请求；API 仅在本人点击测试或发送时调用。把文件交给外部助手后，
适用该助手的数据政策。记录及主动选择持久保存的密钥在本地明文保存，清除不删除已导出文件。

核心与 API 用例：`node --test extensions/autofill/tests/core.test.mjs extensions/autofill/tests/api.test.mjs`。
浏览器验收脚本：`extensions/autofill/tests/browser.mjs`（使用本机 Playwright 和隔离浏览器）。
聚焦回归：`tests/dom-browser.mjs` 验证跨页面写入／撤销与日期控件；
`tests/state-browser.mjs` 验证记录归属、确认状态和失败提示，路径均相对于本扩展目录。
API 浏览器联调：`extensions/autofill/tests/api-browser.mjs`，真实扩展向本机 HTTP 合成服务发请求，
核对默认不发简历值、内容模式、逐项审稿、错误与密钥清理；不冒充真实 DeepSeek / GLM 调用。
用例是合成资料，不证明真实招聘系统接收或面试结果。
2026-10-31 已在本机 Edge 156 验证本地中英文 OCR、PDF 文字提取、
原生字段填入与撤销、草稿逐项确认、记录导出及军师导入。
自动化集成使用仅限 localhost 的测试授权；正式扩展没有预先授予的常驻网站权限，
API 使用时按所填域名申请可选授权。真实工具栏 activeTab 与可选授权弹窗尚未自动化验收。
界面在 320／420 像素侧栏验证了三个页签、方向键切换、草稿确认按钮状态、空搜索结果、
反馈后保留原投简历，以及提示区不覆盖滚动内容。这些检查不等于真人可用性验证。
组件来源和复用边界见 [THIRD_PARTY.md](THIRD_PARTY.md)。
