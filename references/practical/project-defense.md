# Project defense

Choose the riskiest claim. Build this ladder against actual artifacts:

1. What exactly did you implement? Point to the relevant file or reviewed artifact.
2. Why this architecture? Identify constraints and a real decision you owned.
3. Which alternative did you reject, and what would make it preferable?
4. How was the result measured? Baseline, dataset, sample and failure cases.
5. What failed, what did teammates / AI tools do, and what would you change?

For “production”, request real usage / operational evidence. For hackathons, keep
participant status and official award separate. For backtests, explain leakage,
fees and validation; do not substitute profitability for a real execution result.
The risk map must name missing evidence and a safe wording for each break point.
Do not manufacture technical answers beyond the user's demonstrated understanding.
