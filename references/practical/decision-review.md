# Decision review

Compare an earlier decision with new observations and decide the next bounded
action. This host-led review works within the current chat; persistent memory is
optional and remains off unless the user separately consents.

## Establish the earlier decision

Use a visible earlier message or a user-provided record. Preserve its date,
opportunity / project, source, stage, recommended move, evidence, uncertainties,
observation window and reversal conditions where available. A user's recollection
is a sourced recollection, not an exact copy of the old recommendation.

If the earlier record is absent, mark the original recommendation and predictions
unknown. Ask for an excerpt if useful, while still reviewing new observations.
Never invent a prediction, claim an old risk was forecast, or backfill a stop line
to match today's result. Keep retrospective hypotheses explicitly retrospective.

## Separate what happened from explanations

Record the hard recruiting result and its reported source; silence is not rejection.
Then separate observed questions / explicit feedback / artifacts, the user's
feelings and explanations, the agent's interpretations, and remaining unknowns.
Preserve source type: a user recap remains a user recap, even when detailed.

Compare only what the old record actually proposed or predicted. Mark an item
supported, contradicted, not observed, or unassessable for this case, with reasons.
A topic not asked does not show the risk was absent. Passing does not prove the
preparation caused success; rejection does not establish inability or a bad career
direction. Repeated recaps of one event are not independent observations.

Check old reversal conditions against the new evidence. State met / not met /
unknown instead of rewriting them. Separate a newly useful adjustment from a
trigger that was actually recorded before the event.

## Deliver the review and continuation

Deliver `decision-review.md` in chat, or write it only when a file is requested:

- Original judgment and source, or explicit missing-record boundary.
- Actual observations, hard outcome, feelings / interpretations and unknowns.
- Comparison to the old expectation and reversal conditions, including what
  was not observed or cannot be assessed.
- Keep / refine / reconsider with an evidence-based reason; no automatic pivot
  from one outcome. A next preparation priority is not a capability label.
- One next action, real time budget, observation window and stop condition.
- Any Claim correction: project ID, source and stage retained, wording changed
  only as far as evidence supports. An interview pass never upgrades a Claim.

Keep the earlier record intact and label the current correction / review separately.
Return a compact summary the user can carry into this chat next time. Never treat
stored memory as fresh proof, recall unrelated records or auto-enable persistence.
If the user explicitly asks to manage durable memory, follow
[career-memory.md](career-memory.md) and its consent boundaries separately.
