# Role positioning

Translate proven behavior into the role's actual responsibilities. Engineering
experience can support AI PM work when it contains user problem selection, evaluation,
trade-offs and delivery decisions; a title cannot be inferred from technical fluency.

Keep the boundary between personal action and team outcome in the sentence itself.
Use context → personal action → checked result → measurement scope. A small prototype
can demonstrate judgment without pretending it served production users.
For titles, technologies and companies, use only the supplied verified or attributed
facts. Do not “fill in” what comparable resumes commonly contain.

Before polishing, rehearse five layers: exact contribution, choice, rejected alternative,
measurement, failure. If a layer lacks evidence, downgrade wording or add a tiny
evidence task. A project with no validated product outcomes can still be described
honestly as a design and evaluation exercise.
