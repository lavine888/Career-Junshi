# 面试前后闭环：整合与验收

日期：2026-10-24。范围按用户补充收敛为“面试前模拟、面试复盘、面后谈薪”。

## 来源与选择

参考 [Interview Coach](https://github.com/noamseg/interview-coach-skill/tree/634a8dd8689e0420c21e5f0c8ae3cfa9e1a7ab7e)
的选练分流、故事匹配、整场模拟、面后快速回忆和分阶段薪酬沟通方式。
本轮核对的是该固定版本的入口及相关章节，不是全仓库审计。
具体读取范围和许可见 [现有来源审计](ATTRIBUTION.md#interview-coach)。

新增规则独立编写，沿用军师的证据、参考预算和授权边界；未引入上游命令集合、
数值评分及进阶门槛、心理归因、面试官读心或静默状态写入。
不将上游的薪资示例、锚定效应断言或公司谈薪惯例直接当作当前事实。

## 三段如何相接

| 阶段 | 入口 | 下一步 |
| --- | --- | --- |
| 面试前模拟 | interview-coaching；单标准训练仍可用 structured-interview | 从实际回答选一个练习点；整场模拟结束再反馈 |
| 面试复盘 | 同一 coaching 参考中的回忆／转录分支 | 保留实际问答、感受、明确反馈和未知；按记录回到复练或材料修正 |
| 面后谈薪 | 现有 negotiation 参考 | 先判断预期沟通还是 Offer 协商，再做口径比较、请求与单轮演练 |

复用当前机会、Claim/Story ID 和已有接续卡，没有增加候选人数据库或 CLI 模式。
没有录音、未选 JD 或尚无 Offer 都不构成强制初始化的理由。
面试结束、HR 问预期、起草请求、实际加薪分别是不同事件。

## 行为核对范围

[输入](../cases/experiences/interview-loop/request.md)与
[示意对话](../cases/experiences/interview-loop/example.md)由宿主人工编写，用于核对：

- 模拟一次一问，三次实际回答之后才点评，不提前泄露后续问题。
- 回忆不变成逐字稿；追问、感觉不好和“下周联系”不推导拒绝。
- 未给金额时仍能准备一段预期回复，不虚构预算或竞争 Offer。
- 固定月薪 × 明确保证发薪月数与浮动奖金、条件未明的签约金分开。
- 请求使用用户选择的目标金额，私有底线不进入外发草稿。
- 演练中的 HR 限制明确是假设，不制造真实让步或已发送消息。
- 原始职责、证据状态、机会和缺口在三段间保留，不随表达改善自动升级。

这些是合成示意和宿主自查，不是新的独立前向测试，也未测得通过率、涨薪效果
或稳定的自然语言表现。此前的 GitHub 首次使用试用不用于证明本轮能力。
