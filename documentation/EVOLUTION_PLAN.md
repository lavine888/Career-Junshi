# 求职军师体验进化方案

状态：实现与本地验收完成；基于当前本地工作区，保留既有修复与集成改动。
实际检查、独立试用及局限见 [验收记录](EVOLUTION_EVAL.md)。

## 目标与范围

把证据检查与职业判断变成可直接开始、能完成并有明确产物的使用体验。
本轮交付四个宿主驱动入口，重点打磨前两个。沿用现有五个决策模式、
Python 标准库、可选记忆与 1–3 份参考预算；不引入服务、前端、外部发送、
录用概率或候选人综合分数，不自动安装或启用记忆。

| 入口 | 请求示例 | 完成后交付 | 范围 |
| --- | --- | --- | --- |
| 简历守城 / defense | 追问这句简历，直到把个人贡献讲清楚 | resume-defense.md：已讲清 / 缺证据 / 当前安全表述 / 下一步 | 一次一问，依据回答决定后续；可停止并保留未核实项 |
| 岗位表达 / role-translation | 用同一项目适配这些目标岗位 | role-translation.md：共同事实底稿 / 按 JD 的表达 / 取舍依据 / 缺口 | 岗位数由用户材料决定；不强制三版，不补造技能或成果 |
| 补证冲刺 / proof-sprint | 用本周可用时间补一个关键证据缺口 | evidence-sprint.md：目标主张 / 产物 / 验收 / 预算 / 停止线 / 回流 | 七天只是可调整默认；规划不等于完成或认证 |
| 决策复盘 / decision-review | 根据新反馈检查上次建议 | decision-review.md：原判断 / 观察 / 未观察 / 修正 / 下一步 | 不编造旧判断；不开长期记忆也可使用 |

这些是对话体验名，不是新 Skill、现成 slash 命令或新的决策模式。
常规路由仍有效；可选 `route --experience` 只选择参考和说明产物，
不替代宿主推理、运行互动会话或声称已经生成材料。

## 关键决策

- 主提示词只保留入口与关键行为；细节放四份 practical references。
- 所有产物继承来源、自述、个人贡献与阶段边界。未知保留未知，引用只支持原范围。
- 互动题数由材料、风险、时间与用户意愿决定，不把轮数当能力、排名或录用预测。
- 报告可在聊天交付；用户要求文件时再写到其指定目录。分享仅按用户选定内容生成待审草稿，
  不自动附带身份、公司、联系方式或原文材料，不自动发布。
- 普通安装自动带上新参考；校验器必须发现缺失入口资源。保留旧 route/decide 输入兼容性。
- 公开案例全部是合成材料，明确区分示意、单次宿主试用和可重复确定性检查。

## 实施分工

1. Subagent A：简历守城参考与合成演示。
2. Subagent B：岗位表达参考与合成演示。
3. Subagent C：补证、复盘参考与案例。
4. 主代理：主提示词、可选路由、打包校验、使用文档、整合和验收。
5. 独立 subagent：只依据新 Skill 和原始合成请求做前向试用，不提供预期答案。

## 验收清单

- [x] 首次请求可以直接开始；守城首轮只提出一个问题，不预填候选人的回答。
- [x] 同一项目的岗位版本保留同一事实底稿，可指出每项表达对应来源与 JD；证据不足时不硬凑版本。
- [x] 补证计划区分待做与已完成；回传产物后才讨论可支持的措辞。
- [x] 复盘区分原判断、实际观察、个人感觉与未知；无旧记录时不补造预测。
- [x] 常规路由兼容；体验路由不超过三份参考；非法组合明确报错。
- [x] runtime 安装包含新参考，缺失资源可被校验发现，安装不创建记忆。
- [x] 完整 unittest、包校验、Skill 基础校验及合成基准通过；完成差异与未跟踪文件检查。
- [x] 记录独立前向试用的实际结果与局限，不把试用当成真实求职效果。

能否完成、是否采用产物、是否带新 JD 或反馈回来；未经同意不采集材料。
