# 简历定位与结果性质：执行记录

日期：2026-10-22。全部输入与输出为公开合成材料，不使用真人简历、私人目录、
真实投递或招聘结果。

## 本轮改动

- 在既有简历写作参考中加入个人判断提炼：说明本人做了什么选择、约束与依据，
  但不替候选人补写当时未做的判断，也不把团队约定写成个人制定。
- 区分工作范围、观察、团队结果、阶段信号、预测、使用与传播、交付物。
  性质可以重叠，沿用原来源与 confidence，不新增证据账本或可信度等级。
- 全简历改写时按实际目标提议一句定位和最多两条相关证据；证据薄或重复时少写、
  省略摘要。目标不能冒充已任职位，必要的阶段与贡献限制保留在首屏。
- 岗位表达与导出沿用同一底稿。摘要复用现有 sections / entries / bullets、
  source_ids 与 confidence；运行时 JSON schema、模板和 CLI 不变。

这是边界覆盖示例，不能作为五位真人、五项自动语义测试或产品有效性证明。

## 导出与安装兼容性

将 A、B 两组材料组合为一位纯虚构候选人的排版输入，不表示它们来自同一真人。
[输入 JSON](../cases/experiences/resume-positioning/input.json)只用既有 schema；
两条首屏证据复用同一 claim 来源与 SELF_REPORTED，未因摘要化升级可信度。

从当前仓库安装全新临时 runtime，再从安装后的 CLI 导出，输出先放在临时私有
工作目录，仅将公开合成产物复制到 benchmark。回执路径按归档位置重写，实际文件
hash 保留；未覆盖既有安装或生成候选人记忆。

两份实际 XeLaTeX 编译各运行两遍，standard 与 editorial 各生成一页 PDF。
编译、页数、日志、文本覆盖、阅读顺序和重复次数检查均通过。两页实际渲染为
1500 px PNG 并由本轮宿主查看，未发现裁切、重叠、缺字或孤立标题。
对照 A2/A3/B2 普通内容自查后，首屏和项目正文保留团队归属、原型／内部试点阶段
以及题量边界。没有加入真实用户或效率改善结果。

## 局限

五组示例不能证明未知材料下的稳定性、真实用户完成时间或面试／Offer 改善。
结果性质仍依赖宿主核对原始材料；现有导出器只接收已审阅文本，不自动抽取个人
判断、选择卖点或识别数字含义。本轮未增加匹配评分、强制关键词或固定摘要数量。
